# LMS 0.3 版本演进 Spec（考试域拆分 · 作业 · AI 出题出卷 · 判卷）

> 状态：**方案积淀中（未实现）** · 日期：2026-08 · 关联代码：`lms-exam`（拆分）、`lms-learning`（作业）、`lms-ai`（管道）、`lms-media`（附件）、`lms-web`（考试页）
>
> 目标：把考试域从「题库 + 绑定」拆为**题库 / 试卷 / 考试**三个子域；考试独立页面（待考倒计时 + 进入考试）；题库支持**多模态图片供题**；新增 **AI 出题、AI 出卷、AI 语义判卷**；learning 模块新增**作业**功能（与考试并列的积分获取模式，不依赖题库，AI 直接生成概念题）。

---

## 1. 背景与动机

### 1.1 0.2 基线盘点（现状）

| 域 | 0.2 现状 | 0.3 缺口 |
|---|---|---|
| 题目 | `question` 表（单选/多选/判断，答案 JSON）+ `question_biz`（biz_type 1课程/2章节/3考试卷） | 题目只有文本答案，**无附件（图片）字段**；无"上传图片供题"入口；无 AI 出题 |
| 试卷 | ❌ 不存在 | 无组卷概念：从题库抽题、组卷、卷面结构、分值汇总 |
| 考试 | ❌ 不存在 | 无考试编排：考试实例、考生名单、开考时间、倒计时、作答、交卷、判卷 |
| 判卷 | assess-agent LLM 语义批改（评测业务线内） | 判卷与"考试/作业"脱钩，未产品化（独立判卷服务/接口） |
| 作业 | ❌ 不存在 | 无作业功能（AI 生成概念题 → 学生作答 → 判卷 → 积分） |
| AI 出题/出卷 | ❌ 无 | 无生成题目、生成试卷的管道 |
| 前端 | 题库管理页（QuestionManageView） | 无考试独立页（待考倒计时/进入考试） |

### 1.2 0.3 目标（需求原文提炼）

1. **考试模块拆开**：题库、试卷、考试三个子域，均与课程对应；
2. **考试独立页**：列出用户所有待考试（**倒计时**）+ 开考后的**进入考试**按钮；
3. **试卷模块**：从题库抽取题目组合成试卷；题目为 JSON 格式（题干 + 答案 + 附件）；
4. **附件存放形式**：题目附件（一般为图片）——**URL 而非 base64**（见 §2.4 论证）；
5. **AI 语义判卷**：主观/概念题按语义批改；
6. **题库多模态供题**：提供上传题目按钮，支持**图片供题**（OCR/VLM 提取题干）；
7. **AI 出题 + AI 出卷**：生成题目、生成试卷——**都做成管道（工作流）**（见 §5 论证）；
8. **learning 作业功能**：作业 ≠ 考试；都是获取积分、解决问题的模式；作业**不从题库抽题**，由 AI 直接生成概念题。

### 1.3 关键设计决策速览（先回答设计问题）

| # | 问题 | 结论 |
|---|---|---|
| Q1 | 考试模块怎么拆？ | **一个服务三个子域**（lms-exam 内部按子包拆：question/paper/exam），不拆成三个微服务（0.3 阶段单服务够用，拆分点是子包与表）；三个子域共享 `lms_exam` 库 |
| Q2 | 题目附件（图片）用 base64 还是 URL？ | **URL**。附件本体走 lms-media（已有存储抽象），题目 JSON 存 `{"attachments":[{"url","name","type"}]}`。base64 会让 question 表膨胀、无法缓存/复用、查询慢 |
| Q3 | AI 出题/出卷做成工作流吗？ | **是**。复用 lms-ai「固定管道 + 节点 Agent」模式（LearningPipelineService 先例）：出题管道（生成→校验→落库）、出卷管道（抽题→组卷→覆盖校验）。固定产物结构，可校验可回退 |
| Q4 | 作业和考试的关系？ | 并列的两种"解决问题 + 获取积分"模式：考试从试卷（题库抽题）出发；作业**不依赖题库**，AI 按知识点直接生成概念题。两者都走「作答 → 判卷 → 积分」统一闭环 |
| Q5 | AI 判卷怎么实现？ | **LLM 语义判卷为主 + 客观题确定性兜底**（复用 0.2 assess 的 QuestionChecker 模式）：客观题按标准答案 JSON 比对，主观/概念题 LLM 语义批改 |

## 2. 题库子域（lms-exam.question 扩展）

### 2.1 数据模型扩展

```sql
-- question 表扩展（0.3）：附件支持多模态
ALTER TABLE `question`
    ADD COLUMN `attachments` JSON DEFAULT NULL COMMENT '附件列表：[{"url","name","type"}]，图片走 lms-media',
    ADD COLUMN `source_type`  TINYINT DEFAULT 1 COMMENT '题目来源：1 手动录入 / 2 图片供题 / 3 AI 出题',
    ADD COLUMN `source_ref`   VARCHAR(64) DEFAULT NULL COMMENT '来源引用（图片供题=媒资 id；AI 出题=生成任务 id）';
```

### 2.2 题目 JSON 结构（题干 + 答案 + 附件）

> 契约：`docs/api-schemas/ai-tools.schema.json#/$defs/QuestionForm`（工具/接口侧）与 `ai-output.schema.json#/$defs/GeneratedQuestion`（AI 出题产物侧）。

```json
{
  "id": 1001,
  "name": "微服务的核心是什么？",            // 题干（文本）
  "type": 1,                                 // 1单选 2多选 3判断 4主观（0.3 新增主观题）
  "category": "微服务",
  "difficulty": 2,
  "attachments": [                           // 附件（图片等，URL 形式）
    { "url": "/uploads/xxx.png", "name": "图1.png", "type": "image" }
  ],
  "answer": { "option": "A" },               // 客观题：标准答案 JSON（保留 0.2 格式）
  "analysis": "微服务将单体拆分为独立服务…"
}
```

> **附件 = URL 的论证**（Q2）：
> - lms-media 已有统一存储抽象（本地磁盘 → 可换 OSS），上传后返回 url，题目只存引用；
> - base64 弊端：单图 ~2MB→~2.7MB 字符串，1000 题带图 → 数 GB 表；每次列表/详情都拖大字段；无法走 CDN/缓存；图片无法复用。
> - 图片供题链路：前端上传 → `POST /medias/upload`（lms-media）→ 返回 url → 题目 JSON 存 url。

### 2.3 多模态图片供题（上传题目按钮）

| 环节 | 设计 |
|---|---|
| 前端 | 题库管理页新增「图片上传供题」按钮（选择图片/拍照） |
| 上传 | 图片走 lms-media（复用现有上传），返回媒资 url |
| 提取 | lms-exam 收到「图片 + 期望题型」→ 调 lms-ai `question.ingestFromImage` 工具：OCR（RapidOCR 已在 Python 侧验证 / Java 用 PaddleOCR 或 DashScope OCR）提取文字题干 + VLM（Qwen-VL）理解图表语义 |
| 落库 | 提取结果 → 结构化 QuestionFormDTO → 落库 question（source_type=2 图片供题，attachments 存原图 url） |
| 人工确认 | 提取的题干/答案先回显给教师确认再落库（AI 提取非 100% 可靠） |

### 2.4 主观题类型

- `QuestionType` 扩展 `4 主观题`（简答/论述）：`answer` 存参考要点 JSON（非唯一答案），判卷走 AI 语义（§4）；
- 主观题从 0.3 起可用于 AI 出题（概念题天然主观）。

## 3. 试卷子域（lms-exam.paper 新增）

### 3.1 数据模型（lms_exam 库新增表）

```sql
-- 试卷（组卷产物，与课程对应）
CREATE TABLE `paper` (
    `id`          BIGINT       NOT NULL AUTO_INCREMENT,
    `course_id`   BIGINT       NOT NULL COMMENT '课程 id',
    `title`       VARCHAR(100) NOT NULL COMMENT '试卷标题（如：微服务-单元测验）',
    `desc`        VARCHAR(500) DEFAULT NULL COMMENT '试卷说明',
    `total_score` INT          NOT NULL DEFAULT 0 COMMENT '卷面总分（题目分值汇总）',
    `status`      TINYINT      NOT NULL DEFAULT 1 COMMENT '1 草稿 / 2 已发布',
    `source_type` TINYINT      DEFAULT 1 COMMENT '组卷来源：1 手动组卷 / 2 AI 组卷',
    `create_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `update_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    `deleted`     TINYINT      NOT NULL DEFAULT 0,
    PRIMARY KEY (`id`),
    KEY `idx_course` (`course_id`)
) ENGINE=InnoDB COMMENT='试卷';

-- 试卷题目明细（卷面结构：题序/分值/顺序）
CREATE TABLE `paper_question` (
    `id`          BIGINT   NOT NULL AUTO_INCREMENT,
    `paper_id`    BIGINT   NOT NULL COMMENT '试卷 id',
    `question_id` BIGINT   NOT NULL COMMENT '题目 id',
    `seq`         INT      NOT NULL DEFAULT 0 COMMENT '题序（从1开始）',
    `score`       INT      NOT NULL DEFAULT 0 COMMENT '本题分值',
    `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `deleted`     TINYINT  NOT NULL DEFAULT 0,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_paper_question` (`paper_id`, `question_id`),
    KEY `idx_paper` (`paper_id`)
) ENGINE=InnoDB COMMENT='试卷题目明细';
```

### 3.2 手动组卷流程

```
教师选课程 → 按题型/知识点/难度筛选题目 → 勾选并设分值 → 生成 paper + paper_question
接口：POST /papers（draft）→ PUT /papers/{id}（增删题目/调序/改分）→ POST /papers/{id}/publish
```

### 3.3 自动组卷（AI 抽题）

- `POST /papers/auto`：入参 `{courseId, title, questionCount, difficulty?, knowledgePoints?[]}`；
- 服务端按条件从题库筛选候选 → 覆盖知识点均衡（每个知识点至少 1 题）→ 生成 paper；
- 可选走 **AI 出卷管道**（§5.2：LLM 参与选题/排序/拟分值）。

## 5. AI 出题 / AI 出卷 / AI 判卷（lms-ai 管道扩展）

### 5.1 为什么做成"管道/工作流"（回答 Q3）

- 项目已有成熟先例：`LearningPipelineService`（诊断→规划→习题→测评），注释明确"**固定管道 + 节点 Agent 增强**——节点顺序与数据依赖由代码确定，节点内部是带工具的 ReActAgent"；
- 出题/出卷是**确定性产物 + AI 增强**场景：产物结构固定（题目 JSON / 试卷 JSON），需要校验（题型合法性、答案完整性、覆盖均衡）、需要落库、需要可回退——固定管道比"父 agent 自由邀请"更可控；
- 两个管道复用同一套 `runNode` 机制（prompt → ReActAgent → 产物解析 → 校验 → 落库）。

### 5.2 新增管道

> **AI 数据契约（硬性约束）**：本 spec 所有 AI 相关的数据提供（工具入参/出参）必须符合 `docs/api-schemas/ai-tools.schema.json`；AI 返回的结构化内容（管道产物、判卷报告、出题/出卷/作业题 JSON）必须符合 `docs/api-schemas/ai-output.schema.json`。实现顺序：**先定 schema（契约先行）→ 再写 prompt 示例（与 schema 严格一致）→ 再写解析端**。附件一律 URL（走 lms-media），禁止 base64 入库。

| 管道 | 节点 | 产物（JSON Schema） | 校验/兜底 |
|---|---|---|---|
| **出题管道**（question-gen） | ①理解知识点 → ②生成题目（LLM）→ ③结构化校验（题型/答案/难度合法）→ ④落库 question（source_type=3） | `GeneratedQuestionPack`（ai-output.schema.json） | 客观题答案枚举合法；主观题有参考要点；失败重试/丢弃 |
| **出卷管道**（paper-gen） | ①解析需求（题量/知识点/难度）→ ②题库抽题（可 LLM 选题）→ ③组卷排序/拟分值 → ④覆盖校验 → ⑤落库 paper+paper_question | `GeneratedPaper`（ai-output.schema.json） | 题量达标、知识点覆盖、总分合理；不足时 AI 补题 |
| **判卷管道**（judge，复用+产品化） | ①客观题确定性比对（QuestionChecker）→ ②主观题 LLM 语义批改 → ③汇总得分 → ④写回 exam_answer + participant.score + 发积分 | `JudgementResult`（ai-output.schema.json） | LLM 输出解析失败 → 客观题兜底 / 主观题标记"待人工复核" |

### 5.3 与 0.2 评测业务线的关系

- 0.2 `exercise_record`（做题明细）/ `learning_assessment`（测评报告）保留，作为"练习/测评"场景；
- 0.3 考试/作业的作答走新表（`exam_answer` / `homework_answer`），判卷结果**同步回流**一份到 `exercise_record`（错题集原料，诊断管道继续可用）；
- assess-agent 与 0.3 判卷管道共用同一 LLM 判分工具（`exam.getQuestion` + QuestionChecker）。

### 5.4 AI 返回 Schema 校验与重试机制（硬性约束）

**所有 AI 返回点（管道产物、判卷、出题、出卷、作业题、图片提取）都必须经过 JSON Schema 校验；校验不通过必须加标记并严格要求 LLM 重新生成。** 这是 AI 数据可靠性的底线，实现时不可省略。

#### 5.4.1 校验信封（AiEnvelope）

所有 AI 输出统一包一层校验信封（`ai-output.schema.json#/$defs/AiEnvelope`）：

```json
{
  "payload": { "...": "产物本体（DiagnoseReport / GeneratedQuestionPack / JudgementResult ...）" },
  "validation": {
    "valid": true,              // schema 校验是否通过
    "status": "ok",             // ok | needs_review | failed
    "errors": [],               // 校验失败明细（回传给 LLM 要求修正）
    "retryCount": 0,            // 已重试生成次数
    "maxRetries": 2             // 最大重试次数
  }
}
```

#### 5.4.2 校验与重试流程（所有 AI 返回点统一走此链路）

```
LLM 输出原始文本
  → ① 提取 JSON（extractJson，兼容 markdown 代码块包裹）
  → ② Schema 校验（AiOutputValidator：按管道类型加载对应产物 schema，
       用 networknt json-schema-validator 或等价实现严格校验 required/enum/additionalProperties）
  → ③ 通过 → 落库（产物带 validation: {valid:true, status:"ok"}）
  → ④ 不通过 → 判断重试：
       retryCount < maxRetries
         → 将 errors 明细拼进新 prompt（"你的输出未通过校验：<errors>，请修正后重新生成，
            必须符合以下 JSON Schema：<schema>"）→ 重新调用 LLM（retryCount+1）
       retryCount >= maxRetries
         → status = failed：
           · 客观题/可确定性兜底产物 → 走确定性兜底（QuestionChecker），标记 needs_review
           · 主观题/无兜底产物 → 标记 needs_review（待人工复核），不落库或落库标记位
  → ⑤ 落库产物一律保留 validation 信息（valid/status/errors/retryCount），可观测可审计
```

#### 5.4.3 校验规则（按产物类型）

| 产物 | Schema | 强制校验项 | 不通过时的降级 |
|---|---|---|---|
| DiagnoseReport | ai-output | diagnosis/weakPoints 必填 | 重试耗尽 → needs_review，报告不进入规划输入 |
| PlanPath | ai-output | path[] 非空、每步含 knowledgePoint | 重试耗尽 → needs_review |
| ExercisePack | ai-output | questions 非空、questionId 真实存在 | 重试耗尽 → 降级为规则抽题 |
| AssessReport | ai-output | gradedQuestions 非空、每题 questionId/correct/score | **客观题 QuestionChecker 确定性兜底** + needs_review |
| GeneratedQuestionPack | ai-output | questions 非空、每题 name/type/difficulty/answer 合法、答案枚举合法 | 重试耗尽 → 丢弃该题，回显教师手动补 |
| GeneratedPaper | ai-output | questions 非空、questionId 真实、知识点覆盖达标 | 重试耗尽 → 规则抽题补足覆盖 |
| GeneratedHomeworkQuestion | ai-output | seq/name/points 必填 | 重试耗尽 → needs_review，作业题目快照标记 |
| JudgementResult | ai-output | gradedQuestions 每题 questionId/score | 客观题兜底 / 主观题 needs_review（待人工复核） |
| ImageQuestionExtract | ai-output | name/attachments 必填 | 重试耗尽 → 回显原图，教师手动录入 |

#### 5.4.4 实现要求

1. **统一校验器**：lms-ai 新增 `AiOutputValidator` 组件（管道类型 → 产物 schema → 校验），所有管道共用；
2. **重试驱动**：重试次数与错误明细写入 `agent_task` 产物留存（0.2 可观测性机制），可回溯 LLM 修正过程；
3. **标记落库**：产物落库表（exam_answer / homework_answer / question / paper）一律带 `ai_valid`（1/0）、`ai_errors`（JSON）、`ai_retries`（int）三个字段，前端可据此展示"AI 生成待复核"；
4. **严格要求重新生成**：prompt 明确要求"输出必须是合法 JSON 且符合给定 Schema，不满足将被拒绝并重试"；校验失败的重试 prompt 必须携带具体 errors，不得静默接受残缺产物；
5. **禁止静默放行**：任何 AI 返回点不得在未校验的情况下直接落库或进入下游。

#### 5.5.2 校验覆盖矩阵（每落点的重试与降级）

| 落点 | 强制校验项 | 重试策略（maxRetries=2） | 降级/兜底 |
|---|---|---|---|
| 对话（1/2） | text 非空、≤8000 | 空回复重试 1 次 | 返回"生成失败请重试" |
| 画像摘要（3） | summary 非空 | 空摘要重试 2 次 | 保留旧摘要不更新 |
| 诊断（4） | diagnosis/weakPoints 必填 | 带 errors 重试 2 次 | needs_review，不进规划 |
| 规划（5） | path[] 非空、每步 knowledgePoint | 带 errors 重试 2 次 | needs_review |
| 习题（6） | questions 非空、questionId 真实 | 带 errors 重试 2 次 | 规则抽题兜底 |
| 测评判分（7） | gradedQuestions 每题完整 | 带 errors 重试 2 次 | **客观题 QuestionChecker 确定性兜底** + needs_review |
| RAG 改写/HyDE（8/9） | 非空 | 空则重试 1 次 | 用原始 question 检索 |
| RAG 生成（10） | answer 非空 + sources 结构 | 带 errors 重试 2 次 | 返回"知识库无相关内容" + needs_review |
| 图片描述/OCR（11） | text 非空 | 空重试 1 次 | 丢弃该 chunk（入库不阻断） |
| 出题（12） | 每题 name/type/difficulty/answer 合法 | 带 errors 重试 2 次 | 丢弃坏题，回显人工补 |
| 出卷（13） | questionId 真实 + 覆盖达标 | 带 errors 重试 2 次 | 规则抽题补足覆盖 |
| 判卷（14） | 每题 questionId/score | 带 errors 重试 2 次 | 客观题兜底 / 主观题 needs_review |
| 图片供题（15） | name/attachments 必填 | 带 errors 重试 2 次 | 回显原图人工录入 |
| 作业出题（16） | seq/name/points 必填 | 带 errors 重试 2 次 | needs_review，快照标记 |

#### 5.5.3 自由文本 vs 结构化产物的校验分级

- **结构化产物**（诊断/规划/习题/判分/出题/出卷/作业题/图片供题/RAG 答案）：走 `AiOutputValidator` 严格校验（required/enum/additionalProperties），失败带 errors 重试，耗尽降级；
- **自由文本**（对话回复/画像摘要/RAG 改写/HyDE/图片描述）：只校验"非空 + 长度"最小约束，失败重试或降级，不要求 JSON 结构（这些本质是文本生成，硬套结构反而劣化）；
- **中间产物**（RAG rewrite/hyde）：非空校验即可，下游检索有兜底，不强求重试。

## 6. 作业功能（lms-learning 新增）

### 6.1 作业 vs 考试（回答 Q4）

| 维度 | 考试 | 作业 |
|---|---|---|
| 题目来源 | 试卷（题库抽题 / AI 组卷） | **不依赖题库**，AI 按知识点直接生成概念题 |
| 触发方式 | 教师编排（选卷+定时间+考生） | 教师布置（选课程+知识点+题量）或学生自助练习 |
| 时间约束 | 固定开考/截止，倒计时 | 截止时间宽松（或 7 天内完成） |
| 判卷 | 客观题比对 + 主观 AI 语义 | 全 AI 语义判卷（概念题天然主观） |
| 积分 | 完成考试 +EXAM 积分 | 完成作业 +HOMEWORK 积分（PointsType 新增） |
| 共性 | 都是"解决问题 + 获取积分"模式，作答 → 判卷 → 积分闭环一致 | |

### 6.2 数据模型（lms_learning 库新增）

```sql
-- 作业
CREATE TABLE `homework` (
    `id`          BIGINT       NOT NULL AUTO_INCREMENT,
    `course_id`   BIGINT       NOT NULL COMMENT '课程 id',
    `title`       VARCHAR(100) NOT NULL COMMENT '作业标题',
    `description` VARCHAR(500) DEFAULT NULL COMMENT '作业说明',
    `knowledge_points` VARCHAR(255) DEFAULT NULL COMMENT '知识点（逗号分隔，AI 出题依据）',
    `question_count` INT        NOT NULL DEFAULT 5 COMMENT '题目数量',
    `deadline`    DATETIME     DEFAULT NULL COMMENT '截止时间',
    `status`      TINYINT      NOT NULL DEFAULT 1 COMMENT '1 已发布 / 2 已截止',
    `create_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `update_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    `deleted`     TINYINT      NOT NULL DEFAULT 0,
    PRIMARY KEY (`id`),
    KEY `idx_course` (`course_id`)
) ENGINE=InnoDB COMMENT='作业';

-- 作业题目（AI 生成的概念题，存作业快照，不占题库）
CREATE TABLE `homework_question` (
    `id`          BIGINT        NOT NULL AUTO_INCREMENT,
    `homework_id` BIGINT        NOT NULL COMMENT '作业 id',
    `seq`         INT           NOT NULL DEFAULT 0 COMMENT '题序',
    `content`     JSON          NOT NULL COMMENT '题目 JSON（题干/参考要点，含图片附件 url 可选）',
    `create_time` DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `deleted`     TINYINT       NOT NULL DEFAULT 0,
    PRIMARY KEY (`id`),
    KEY `idx_homework` (`homework_id`)
) ENGINE=InnoDB COMMENT='作业题目快照';

-- 作业作答
CREATE TABLE `homework_answer` (
    `id`          BIGINT        NOT NULL AUTO_INCREMENT,
    `homework_id` BIGINT        NOT NULL COMMENT '作业 id',
    `user_id`     BIGINT        NOT NULL COMMENT '学生',
    `question_id` BIGINT        NOT NULL COMMENT 'homework_question.id',
    `user_answer` VARCHAR(4000) DEFAULT NULL COMMENT '作答（文本）',
    `score`       INT           DEFAULT NULL COMMENT 'AI 判卷得分',
    `comment`     VARCHAR(500)  DEFAULT NULL COMMENT 'AI 评语',
    `ai_valid`    TINYINT       DEFAULT 1 COMMENT 'AI 判卷产物 schema 校验：1 通过 / 0 未通过（§5.4）',
    `ai_errors`   VARCHAR(1000) DEFAULT NULL COMMENT 'AI 产物校验失败明细（JSON）',
    `ai_retries`  INT           DEFAULT 0 COMMENT 'AI 判卷重试次数',
    `create_time` DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `deleted`     TINYINT       NOT NULL DEFAULT 0,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_homework_user_question` (`homework_id`, `user_id`, `question_id`)
) ENGINE=InnoDB COMMENT='作业作答';
```

### 6.3 作业流程

```
教师布置作业（选课程+知识点+题量+截止）→ 调 AI 出题管道（按知识点生成概念题快照）
  → 学生端作业列表（截止倒计时）→ 作答（文本）→ 交作业
  → AI 语义判卷（每题打分+评语）→ 总分 → HOMEWORK 积分 + 错题回流 exercise_record
```

| 阶段 | 内容 | 验收标准 |

| **P1 考试域拆分（题库/试卷/考试）** | question 扩展（附件/主观题/来源）；paper/paper_question 表；exam/exam_participant/exam_answer 表；手动组卷 + 考试编排 + 考试页（倒计时/进入/交卷） | 教师组卷发布 → 学生待考列表倒计时 → 进入考试作答交卷 → 客观题判分回显 |

## 11. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 图片供题 OCR/VLM 提取不准 | 题干/答案错误入库 | 落库前人工确认回显；source_type 标记可追溯 |
| AI 出题答案不严谨 | 题目质量差 | 客观题答案枚举校验；主观题参考要点 + 教师确认；问题题目可下架 |
| AI 语义判卷不稳定 | 分数不公 | 客观题确定性兜底；主观题 LLM 输出解析失败标记"待复核"；评分 rubric 注入 prompt |
| 考试超时/倒计时作弊 | 公平性 | 后端提交时校验 end_time/duration + 服务端时间，不以客户端倒计时为准 |
| 作业 AI 生成题目与题库重复 | 出题同质 | homework_question 快照独立存储，不与题库混用（设计如此，天然隔离） |
| 判卷回流 exercise_record 与考试作答双写 | 数据不一致 | 考试作答为主，回流仅作错题集原料；按 source 区分，可重建 |

## 12. 质量检查清单（对齐技能包）

- [ ] **AI 返回必过 Schema 校验（§5.4 硬性约束）**：所有 AI 返回点（出题/出卷/判卷/作业题/图片提取/诊断/规划/习题/测评）经 `AiOutputValidator` 严格校验；不通过 → 加标记（needs_review/failed）+ 携带 errors 严格要求 LLM 重新生成（retryCount < maxRetries）；禁止静默放行未校验产物；
- [ ] **链路追踪**：出题/出卷/判卷管道产物落 agent_task（含 validation.retryCount/errors），可回溯生成与修正过程；
- [ ] **幂等**：交卷（uk_exam_user / uk_participant_question）、作业提交（uk_homework_user_question）防重复；
- [ ] **降级**：LLM 不可用 → 客观题判定可用、主观题标记待复核；图片提取失败 → 回显原始图片让教师手动录入；
- [ ] **安全**：考试/作业附件 url 走 lms-media 鉴权；判卷评分 rubric 注入防注入；
- [ ] **性能**：试卷拉取一次查 paper_question + question 批量；倒计时在前端 + 后端校验兜底；
